# Local platform remediation — 2026-10-21

This is an uncommitted local working-tree assessment, not a release candidate or an approval to deploy. Existing July release identifiers and images do not attest these changes.

## Implemented

- Reject missing or invalid actors in legacy request-facing access helpers. Use the shared organisation/site resolver, preserve multiple assigned sites, and deny access when memberships or the user are absent.
- Restrict site operators' alarm and incident queries to their assigned sites. Deny changing another site's rules and creating or changing organisation-wide rules through site-only access.
- Separate access and refresh JWT purposes, require valid identity and expiry claims, and issue unique token IDs. Refresh credentials are rejected at HTTP and socket access gates. **Deployment requires all existing users to sign in again**: legacy tokens without a purpose are deliberately rejected.
- Use Express's configured proxy resolution for admin IP and HTTPS checks, including HTTPS enforcement. A caller-supplied forwarding header no longer overrides the trusted network boundary. Production proxy hops must match the actual hosting topology.
- Filter Zolt reading tools and forecast-job capacity inputs to the operating environment; live analysis excludes simulated sources.
- Add fresh fleet power snapshots: one most-recent reading per active node, at most 60 seconds old. Historical sample averages remain separate. Frontend streaming totals preserve the latest sample per node, count zero readings, and expire stale samples.
- Correct kW/MW and voltage display mismatches. Remove unsupported main-dashboard revenue, accuracy, hydrogen and trend figures; remove inferred asset capacities and inferred wind/solar identification on the generation page.
- Remove an unused canned AI-response function. Existing illustrative insight screens remain labelled as demonstration content.
- Address unused code, unsafe `any` casts and hook dependency warnings; separate reusable context hooks from provider components.
- Use a dedicated browser-test port, forbid reuse of another server, and bound browser concurrency. Correct outdated paths in the route smoke script.
- Add `npm run verify:local` with source fingerprinting and machine-readable local results.

## Verification

Run `npm run verify:local` from the active application directory. The generated `go-live-reports/local-verification.json` is the authoritative result for the exact local source fingerprint it contains. A failed step stops the run, records failure and exits nonzero. Source changes during verification invalidate the result.

The browser suite uses mocked API responses. Backend regressions use mocked persistence; they do not establish production database migration compatibility, live performance, provider accuracy or hardware behaviour.
