# Production blocker remediation — 2026-10-22

This record covers local engineering changes. It is not deployment approval,
independent security approval, a hardware bench result, or proof of customer savings.
The canonical external gate ledger remains
[`evidence-completion-board.md`](../runbooks/evidence-completion-board.md).

## Changes

- Readiness now returns 503 if mandatory Redis is unavailable. Health probes no
  longer consume the customer API rate limit, while normal API requests remain limited.
- Health exposes the operating mode and physical execution flags. The staging
  and production verification commands require an expected full commit SHA and
  image digest, healthy database and Redis, a live advisory operating mode,
  and the physical execution lock. They reject a different deployed release.
- Verification supplies the frontend Origin during refresh, bounds network
  requests, rejects redirects, omits response bodies from errors, and writes a
  failed report rather than leaving an earlier successful staging/production report.
- Docker startup now verifies a real vault encrypt/decrypt round trip after
  migrations. Explicit DIRECT_URL configuration is preserved by Render startup.
- Compose defaults to PILOT_LIVE and requires release identity, with physical
  execution disabled. The root Render Blueprint now includes missing safety,
  vault and observability configuration, explicit browser fallback routing,
  locked dependency installs, and manual deployment. Its existing source-built
  backend is staging and explicitly does not claim signed-image identity.
- The current remote repository already has its application and workflows at
  the repository root, unlike the outer local workspace. This branch uses that
  remote layout. CI now runs release-verifier regressions, and image publication
  depends on the full existing CI workflow through workflow_call, retaining
  its signing, SBOM and provenance steps. New branch CI evidence is pending.
- Removed the expired vulnerability exception after both production dependency
  audits passed without exceptions.
- Signed-load tools use the API's millisecond clock. Concurrent ingest workers
  require distinct devices and credentials. Dropped load iterations fail the test.
  Replay validation first requires an accepted signed request, then rejects
  auth failures and rate limiting as evidence of replay protection.
- Browser journeys now wait for clickable controls instead of forcing clicks
  during transitions or swallowing retry-click failures.
- Local verification fingerprints now also cover deployment workflows, Docker,
  startup scripts, load harnesses, firmware sources and vulnerability policy.
